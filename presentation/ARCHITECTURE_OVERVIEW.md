## Схема 1: Из чего состоит система (5 блоков)

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  [1] ИСТОРИЧЕСКИЕ ДАННЫЕ                                    │
│       Oracle DB: 15 лет × 15 мин = ~500K записей           │
│       - 64 управляющих параметра (что делало оборудование)  │
│       - 36 сенсоров (каким был климат в ответ)             │
│                    │                                        │
│                    ↓ обучение                               │
│                                                             │
│  [2] LSTM-МОДЕЛЬ (цифровой двойник)                        │
│       Нейросеть, которая выучила:                           │
│       "если дать такие 64 команды, то через 15 мин         │
│        сенсоры покажут вот это"                             │
│                    │                                        │
│                    ↓ используется как                       │
│                                                             │
│  [3] СРЕДА СИМУЛЯЦИИ                                        │
│       "Игровой движок": алгоритм даёт команды →            │
│       среда возвращает состояние сенсоров → и так по кругу │
│                    │                                        │
│                    ↓ взаимодействует с                      │
│                                                             │
│  [4] АЛГОРИТМ УПРАВЛЕНИЯ                                    │
│       (студенческий, автоматический, или RL-агент)          │
│       Смотрит на 36 сенсоров → принимает решение →         │
│       выдаёт 64 команды                                     │
│                    │                                        │
│                    ↓ результаты идут в                      │
│                                                             │
│  [5] СИСТЕМА ОЦЕНКИ                                         │
│       Считает: комфорт + энергоэффективность + стабильность │
│       Формирует итоговый балл (leaderboard)                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**Ключевая идея:** блоки [2] и [3] вместе — это "цифровой двойник". Он позволяет тестировать любой алгоритм [4] без риска навредить реальному оборудованию.

## Схема 2: Логика управления — MPC (Model Predictive Control)

```
Каждые 15 минут:

  ┌─────────────────────────────────────────────────────┐
  │  1. НАБЛЮДЕНИЕ                                      │
  │     Считываем 36 сенсоров → текущий климат         │
  │                    ↓                                │
  │  2. СРАВНЕНИЕ С ЦЕЛЬЮ                               │
  │     Целевые параметры климата — заданы заранее,     │
  │     не меняются                                     │
  │                    ↓                                │
  │  3. ПРИНЯТИЕ РЕШЕНИЯ                                │
  │     Климат в норме? ──ДА──> Следуем плану           │
  │          │                  (берём след. команду    │
  │          НЕТ                 из 2-дневного плана)   │
  │          ↓                                          │
  │     Пересчитываем план на 2 дня вперёд              │
  │     (используем LSTM для симуляции)                 │
  │                    ↓                                │
  │  4. ДЕЙСТВИЕ                                        │
  │     Выполняем ПЕРВУЮ команду нового/старого плана   │
  │                    ↓                                │
  │  5. Ждём 15 мин → повторяем с шага 1               │
  └─────────────────────────────────────────────────────┘
```

**Приоритеты:**

-   Достижение целевого климата — ВСЕГДА важнее строгого следования плану
-   План пересчитывается автоматически при отклонении от цели
-   LSTM используется для расчёта плана: "что будет через 2 дня, если дать такие команды?"

**Промышленный термин:** этот подход называется **MPC — Model Predictive Control**. Это стандартный метод в промышленной автоматизации (нефтехимия, энергетика, HVAC). Его применение здесь — не экзотика, а проверенная практика.

## Схема 3: Экономика управления — почему точный прогноз = экономия денег

```
СЦЕНАРИЙ A: Хороший алгоритм (точный прогноз)
──────────────────────────────────────────────
  2 дня назад: рассчитан план управления
       ↓
  Закуплена дешёвая энергия по плану (day-ahead рынок)
       ↓
  Фактический климат ≈ прогнозу → план выполняется
       ↓
  РЕЗУЛЬТАТ: дешёвая энергия, климат в норме ✅ 💰

СЦЕНАРИЙ B: Плохой алгоритм (неточный прогноз)
────────────────────────────────────────────────
  2 дня назад: рассчитан план управления
       ↓
  Закуплена дешёвая энергия по плану
       ↓
  Фактический климат ≠ прогнозу → нужна срочная коррекция
       ↓
  Экстренная закупка энергии по spot-цене (в 3-5x дороже)
       ↓
  РЕЗУЛЬТАТ: дорогая энергия, перерасход бюджета ❌ 💸
```

**Вывод для директоров Biosphere 2:**

> Качество алгоритма управления напрямую влияет на стоимость эксплуатации. Цифровой двойник позволяет найти и протестировать лучший алгоритм ДО того, как он будет запущен на реальном оборудовании.

**Аналогия:** Это как управление энергопотреблением завода — отклонение от заранее поданной заявки на электроэнергию стоит в разы дороже плановой.
